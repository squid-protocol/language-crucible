# yaml corpus sources

Provenance recorded 2026-08-28 as part of the issue #4 audit (squid-protocol/language-crucible#4 — full per-repo attribution across `data/`) for the pre-existing `ansible` folder, and at copy time (`exact`) for the six folders added 2026-09-03 for issue #23. See the root `SOURCES.md` for the full methodology and what each confidence level means.

GitGalaxy's `yaml` standard targets the CI/CD dialects — its `_meta.target_version` is "YAML CI/CD (GitHub Actions / GitLab CI)" and its `discriminators` name `.github/workflows`, `docker-compose.yml` and `openapi.yaml` — so this category is deliberately weighted toward those ecosystems rather than generic key/value YAML (issue #23: the previous Ansible-only sample fired 1 of 32 rules; this set fires 31 of 32). The one rule with no positive example is `hardcoded_secrets`, by design: it matches committed 16+-character quoted secret values, which well-maintained upstreams don't have — the category exercises it as a negative. Also a pool ceiling worth recording: no OpenAPI spec in the pool under the 60 KB size cap carries an `info.contact:` block (the two that do are 188 KB and 456 KB), so `ownership`'s `contact:` alternation is exercised only via `author:` here.
